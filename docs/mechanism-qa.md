# 机理校验问答

## 使用

1. 在“知识文档”上传并解析文件，在 AI 助手的“知识库”分页把文件加入知识库。
2. 打开 AI 助手 →“机理校验问答”，选择知识库，输入问题及完整的 BSM1 工况，包括干／雨季入流、负荷系数和是否先稳态初始化。当前支持 1–13.9 天仿真、1–13 天整数评价窗口；参数硬限读取当前仿真 profile。
3. 选择指标，输入待核对值、单位、统计时间窗、统计方式、数据场景、指标定义，以及该数值对应的入流、负荷系数和初始化条件。若条件未知，应选择“未知”或留空统计天数。
4. 提交后会依次看到排队、模型计算和资料复查／问答状态。完成页保留输入、模型原始指标、差异、比较规则、结论、文档版本／段落出处与仿真任务 ID。点击“查看分块”可检查引用原文。

当前校验的是**给定 BSM1 标准工况下的数值对照**。页面上的“结果相符”仅表示用户提供的同定义、同入流、同统计窗口数值落入本项目配置的比较阈值；不是传感器校准、现场数据真实性证明或本厂工艺模型校准。标记为“本厂监测数据”的记录会得到“模型不适用”，但仍展示模拟值以供参考。缺少入流、定义或时间窗则为“条件不足”。定义或入流明确不同也属于“模型不适用”。

页面默认将待核对数据的场景、单位、指标定义、对应入流、负荷系数、初始化条件和统计方式标为“未知”，统计时间窗留空。用户需要依据原始记录主动确认，页面不会自动把 BSM1 工况填成待核对数据的条件。

首版由用户输入待核对数值。系统检索并引用相关文档，但不自动从自由文本推断数值、单位、入流和统计窗口；填写时应按引用原文逐项核对。若文档中的数值与模型输出冲突，结构化结论按输入值和固定规则判定，文档原文仍作为独立出处展示。

## 指标与规则

模型实际输出的以下 7 个指标参与比较。绝对差为 `|待核对值－模型值|`，相对差为 `绝对差／模型值 × 100%`。比较前将 `g/m³` 按 `1 g/m³ = 1 mg/L` 转为浓度单位；不自动换算其他单位。判定采用未四舍五入的原始数值，页面的差异显示最多 6 位小数。

| 指标 | 模型字段 | 单位 | 统计方式 | “相符”阈值 |
| --- | --- | --- | --- | --- |
| 出水氨氮均值 | `effluentSnhMean` | mg/L | 评价窗口均值 | 绝对差 ≤ 0.5 mg/L |
| 出水悬浮物均值 | `effluentTssMean` | mg/L | 评价窗口均值 | 绝对差 ≤ 2 mg/L |
| 出水硝态氮均值 | `effluentSnoMean` | mg/L | 评价窗口均值 | 绝对差 ≤ 0.5 mg/L |
| 第 5 格溶解氧均值 | `doTank5Mean` | mg/L | 评价窗口均值 | 绝对差 ≤ 0.2 mg/L |
| 日均曝气能耗 | `aerationEnergy` | kWh/d | 评价窗口内日均 | 相对差 ≤ 5% |
| 日均泵送能耗 | `pumpingEnergy` | kWh/d | 评价窗口内日均 | 相对差 ≤ 3% |
| 日均搅拌能耗 | `mixingEnergy` | kWh/d | 评价窗口内日均 | 相对差 ≤ 2% |

这些阈值是首版产品配置的**对照容差**，分别考虑浓度指标的绝对量级和能耗指标的相对量级；尚未通过现场数据估计测量不确定度，也不是法定达标限值。正式用于具体厂站前应利用实测数据校准模型与各指标阈值。远端新版已对 EQI 做官方基准对照，但本问答模块尚未定义 EQI 的待核对数据口径和专属比较阈值，因此首版仍不比较 EQI。零模型值不适用相对差阈值，返回“条件不足”。

## 流程与可追溯记录

`POST /api/mechanism-qa` 要求 `query`、`knowledgeBaseIds`、完整 `params` 和 `observed`。后端先调用现有 `retrieval.run`／`retrieval.refresh`，保存检索任务及文档、版本、分块、修订身份，再通过 `simulation.enqueue` 创建 BSM1 任务。`GET /api/mechanism-qa/:id` 返回排队／运行进度；仿真完成后，后端按关联任务 ID 从 `sim_jobs` 和 `sim_results` 读取状态、参数及原始指标，检查结果 schema、profile、模型／代码版本、入流哈希和工况回显。浏览器无法提交仿真结果。文档在仿真运行期间可能变化，所以生成回答前重新检索与复查，保存最终引用身份及检索任务 ID。

`mechanism_qa_runs` 保存问题、知识库 ID、工况、待核对数值与条件、初始及最终检索任务 ID、引用快照、仿真任务 ID、模型原始指标、比较规则快照、程序判定、回答和错误状态。结构化比较先写入数据库，再调用当前启用的 LLM。文档段落在 LLM 消息中只作为不可信引用文本；LLM 只解释证据，不计算偏差或决定结论。回答带 `[文档N]` 和 `[仿真:任务ID]`，页面以结构化卡片为判定依据。

仿真失败时保留已取得的检索段落；重新检索或 LLM 失败时保留仿真指标与比较卡片，并返回 `partial` 状态和实际错误。进程在生成回答时中断，重启后可由后续轮询重新触发。当前服务仍按本机单用户模式设计，未建立按用户隔离的读取权限，也未设校验记录自动清理策略。

### API 请求示例

```json
{
  "query": "此工况下出水氨氮 3.2 mg/L 与模型是否一致？",
  "knowledgeBaseIds": ["知识库 UUID"],
  "params": { "influent": "dry", "horizonDays": 13.9, "evalDays": 7, "doSetpoint": 2, "recycleRatio": 3, "carbonDose": 0, "loadFactor": 1, "stabilize": true },
  "observed": { "metric": "effluentSnhMean", "value": 3.2, "unit": "mg/L", "windowDays": 7, "statistic": "mean", "dataContext": "benchmark", "definition": "bsm1", "influent": "dry", "loadFactor": 1, "initialization": "stabilized" }
}
```

`GET /api/mechanism-qa/metrics` 返回后端支持的指标与阈值，页面用它生成选项和规则提示。`GET /api/mechanism-qa/:id` 返回完整的结构化卡片和回答。普通 `/api/knowledge/query` 与 `/api/simulation` 的既有请求格式不变。

## 验证

运行 `npm run check`、`npm run test:mechanism-qa` 和 `npm run test:retrieval:unit`。机理校验测试覆盖正常对照、单位／时间窗／统计方式不匹配、缺失参数、仿真任务参数及结果不一致、仿真失败、LLM 失败，以及文档记录数值与模型输出冲突时的确定性判定。完整服务联调还需 PostgreSQL、Ollama 和 simulator 运行；首次运行将执行仿真 worker 的 JIT 预热。
