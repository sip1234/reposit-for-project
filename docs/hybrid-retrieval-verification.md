# 混合检索与重排验证记录

日期：2026-10-30（Asia/Shanghai）。实际环境：本项目 Docker Compose、PostgreSQL/pgvector、Ollama、独立 CPU ONNX 重排服务及浏览器。未提交或推送 GitHub，未部署到外部环境，未切换现有默认问答或 embedding 模型，未调用保存的 DeepSeek 密钥。

## 实际模型和迁移

- 原有 Qwen3 Embedding 0.6B，1024维；新增非默认 `paraphrase-multilingual:278m`，768维，约562 MB。两种**不同权重、不同维度**模型均实际完成查询向量生成及距离检索；第二种模型仅应用于专用评测的 ST-04 文档。
- 实际重排为 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`，固定资源版本见使用说明，ONNX AVX2 量化 CPU 推理。缓存本机实测135702676字节，包含权重及 tokenizer 等资源；不是接口占位或模拟分数。
- 首次升级前895个文档版本分块，升级后仍为895；最终再次按版本创建时间核对，原有895个分块全部保留。新增的评测/回归资料使总数增至1279，派生词项列缺失数量为0。未对生产资料统一重新解析。
- `hybrid-retrieval-v1` 与 `hybrid-lexical-v1-verified` 已实际执行并经多次 API 重启验证幂等。GIN 查询计划实测 Bitmap Heap Scan → Bitmap Index Scan `parsing_chunk_lexical_gin`；设备词项样例查询约0.1 ms，不代表大规模检索总耗时。
- 默认值最终仍为原来的 deepseek/deepseek-flash 和本地 Qwen3 Embedding，新增模型均非默认。页面保存配置后系统检索默认ID也保持不变。

## 人工标注检索评测

固定样例在 `tests/retrieval-cases.json`：16篇工艺小文档，另加1篇重复上传资料，知识库共17个文件。12个问题各人工指定1个相关文档，覆盖中文同义表达、曝气节能语义、P-101/P-101A、ST-04/ST-40、DO/NH4-N/PAC/SRT、数值与Unicode单位、英文CIP。重复上传的同内容来源合并后保留 alternateSources，相关性计算同时检查代表及保留来源，不以“返回任意结果”为成功。

最终版本复用同一批资料，不上传或重新解析；预热当前实际向量模型，预热不纳入指标。在每个问题上运行仅关键词、仅向量、混合、混合加真实重排；断言混合和重排的**融合候选身份集合完全相同**，比较排序而非改变召回池。

主要参数：关键词40、每模型向量30、融合80、重排40、最终5、每文件2，最低余弦0.1（为评测对比显式覆盖生产默认0.25）；默认RRF k60、两路总权重各1；未启用最低logit筛分。17个文件分配为16个Qwen/1个Paraphrase，存在明显路内资料数不均衡。

重排前资格复查、范围/资格统计等其余阶段在逐请求JSON中保留。上述服务器管道耗时不含浏览器网络、配置前置校验、记录持久化和调用方额外返回复查；不是端到端 SLA。首次冷加载曾明显慢于预热结果，本表使用同轮预热后的平均值。

这组小样例中重排**没有继续提高**混合已经达到首位命中的指标，却增加实际耗时；不能据此声称所有问题都会改善。仅向量分数没有跨模型直接混排；单文档模型容易在其路内取得第一名，造成RRF排名偏置，也是本轮向量MRR下降的原因之一。混合关键词信号纠正了这一组样例的排序。

每题只有一个标注相关目标，因此本轮Recall@K等于目标是否出现在前K的平均值，nDCG为单个二值相关目标的折损收益；不是多相关文档的完整召回评测。样例由开发阶段人工构造，规模小、主题窄、无独立人工复核或统计显著性结论；不可用于宣称生产准确率100%。

原始逐问题、逐模式结果：`artifacts/retrieval/final-evaluation.json`；首轮单模型建库与功能测试报告为 `evaluation.json`。两份报告使用不同阶段的模型分布，不混合统计。保存的实际检索记录可按报告的runId在页面查看。

13组一致性/故障/资源断言：

1. 真实CJK、编号、十进制及单位词项；实际GIN执行计划。
2. 将专用样例置为停用、pending、processing、failed、正文/向量修订不符、零向量和错误维度，分别检查关键词、向量、混合和重排都不召回。
3. 在**真实问题向量调用期间**暂停测试流程，实际修改正文、停用或切换有效版本；资格复查剔除旧身份。数据库1秒锁超时下这些修改均成功，证明模型调用时没有持有分块行锁。
4. 检索中移除知识库成员，返回前不泄漏该文件。
5. **真实交叉编码器已算分后**再停用资料，旧重排结果剔除。
6. 独立本机HTTP故障注入覆盖503、数量不符、非法分数、重复索引、资源版本不符和非法JSON；分别验证严格报错与明确降级，降级没有rerankScore。
7. 真实HTTP延迟触发Abort超时，返回504或按配置降级；不是固定分数替代。
8. 测试进程内注入embedding不可用；混合仅可降级到资格正确的关键词，仅向量全部失败返回错误。
9. **真实本地LLM回答生成后**修改资料，整个旧回答隐藏，不返回失效引用。
10. 字符预算包含引用头，编号仍连续且归属不变。
11. 使用真实重排分与很高的可选logit门限，候选被如实过滤，不拿融合分套门限。
12. 四个实际检索请求处于进行中，第五个被503拒绝；前四个释放后正常完成，无无限排队。
13. 两个真实交叉编码请求同时发送、各40候选；一个完成40条实际评分，一个返回429。

第二项是负向数据故障注入，processing等状态并不声称来自一次完整生产任务。真实worker失败/恢复另由`test:chunks`执行。HTTP错误响应注入只验证防护，**不参与检索效果指标**；评测、长文、正常重排和本地问答都实际调用模型。

## 未验证与未实现

已实现并验证的是本机x86-64 CPU、固定ONNX量化重排资源、两种真实向量模型以及上述小样例。没有仅用接口或模拟排序冒充完成的重排能力。

尚未验证ARM、GPU后端、其他重排权重、外部服务、百万级资料、复杂真实生产语料及高并发长期运行；外部重排、词典分词/BM25、拼写纠错、长文窗口重排、动态多维ANN、在线分批大库索引初始化和自动记录清理目前没有实现，不作为已交付能力。现有单用户权限边界不等同于团队或多租户授权。
